## 2. Lessons candidates (engineering discoveries of this run)

| # | Candidate lesson | Evidence |
|---|------------------|----------|
| L1 | espeak's British English (`en-gb`, Kokoro's `b` voices) is non-rhotic in isolation ("for" → `fɔː`) and pronounces a linking r before a vowel in context ("for a" → `fəɹə`); any identification evidence built from per-word phonemes must allow that `ɹ`, and must count syllables per word rather than on the joined forms (vowel-final + vowel-initial words merge into one run). The first full matrix failed P0-2 on exactly this unit at all 25 rates; the fix changed no table and no span. | `phase0/MAPPING_POLICY.md` §4; journal S1 00:15; `lib/wordmap.mjs` |
| L2 | A generation log's "0 fails" counts exceptions only; a table-level verdict (`reconciled: false`) is visible only in the summary. Gate on the summary's exit code, never on the log. | journal S1 00:15 |
| L3 | Kokoro (`model_q4.onnx`, kokoro-js 1.2.1) renders the leading silence of a chunk at roughly 360–500 ms regardless of speed, while the BOS token's predicted duration scales with 1/speed (575 ms at 0.80x → 225 ms at 2.00x); the table's first word is therefore late by 40–120 ms at ≤ 1.00x and early by 50–150 ms at 2.00x. At interior word onsets after a pause the table is late by about two native frames divided by speed (means +63 ms at 0.80x, +47 at 1.00x, +36 at 1.40x, +9 to +30 at 2.00x; reference uncertainty ≤ 9.5 ms). | `phase0/acoustic/*.json`; VERDICT.md part (ii) |
| L4 | onnxruntime-node's default thread count was the slowest setting on this host for Kokoro (worst warm 4.5 s); 4 intra-op threads was best (2.0 s); 8 oversubscribed (3.1 s). The first generation at a new input shape costs about twice a repeat (3.2–4.1 s vs 1.6–1.8 s for 11 words), so a harness that repeats one text is optimistic for a product whose chunks change shape every time. | `phase0/latency.threads-*.json`; `phase0/latency.json`; VERDICT.md P0-5 |
| L5 | Running the generation matrix while anything else loads the CPU inflated per-chunk generation time by about 40 % (3,654 s under load vs 2,612 s quiet for the same 500 chunks, byte-identical audio); timing fields in tables are only comparable when recorded on a quiet machine. | journal S1 01:10 |
