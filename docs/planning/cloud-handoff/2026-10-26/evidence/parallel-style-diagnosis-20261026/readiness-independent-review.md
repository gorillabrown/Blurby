## Guard and real continuation

At View.render (277–282), retain the early no-layout return, capture const doc = this.document, then return for !doc or (doc.readyState === 'loading' && !doc.body). Leave the subsequent layout state and columnize/scrolled dispatch unchanged. This preserves existing absent-document behavior, while delaying only an observed incomplete body. A loading document whose body already exists must dispatch normally. A complete or interactive document lacking body must continue to the existing observable invalid-state error; no unconditional !body return, catch, logger filter or helper null guard.

View.load's existing once load callback (246–272) calls afterLoad, computes styles/direction, touches and selects doc.body, obtains current layout through beforeRender, then calls this.render(layout), observes body and resolves. For a still-live successful document load with a body this is a real later continuation, with freshly calculated layout; no timer, replay queue, cached skipped layout or second load listener is needed. The initial skipped request need not mutate #column/#layout because the load callback supplies the actual layout. Test that the layout used at continuation reflects current dimensions/flow after a pending resize or setting change.

Capturing doc in the render entry does not make scrolled/columnize use that local variable: those methods reread the iframe Document. There is no await/task boundary between guard and dispatch, so ordinary navigation completion cannot interleave there. Do not claim atomic document ownership across asynchronous load/replace/destroy from that capture. Passing doc through helper signatures is not justified by current evidence.
