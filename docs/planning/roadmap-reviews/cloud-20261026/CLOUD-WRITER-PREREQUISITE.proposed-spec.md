## Tasks — exact selected contracts
### 1. Successful payload provenance
Extend conditionalWrite INTERNAL outcome to retain an immutable copy of the exact payload bytes/hash and actual returned etag/generation for the attempt that succeeded, including retries. Preserve retry count/storage API/production conflict and merge rules. Original downloaded raw cloud bytes/data and EACH retry's raw freshData/hash/revision/etag remain separately identified from merged/written payload. Prior merged unions never masquerade as fresh remote. Failure/exhaustion/abort returns no successful upload/merge, successful hash/operation clear/completed-sync advancement. Preserve earlier per-file success as partial evidence, not an atomic multi-file transaction.
syncFile/caller distinguish observed raw remote, actual successful write and local apply. Retry-derived fresh cloud data can require local apply even when the initial branch was uploaded. Revalidate current local content/replacement/account authority; use CURRENT local docs and applicable ORIGINAL raw remote operand with existing mergeLibrary and GC ordering. A post-write rebase is not proof rebased bytes were uploaded. Cache hashes only for actual observed/written bytes in current account/init ownership; report remote/local divergence and retain newer work. Exact PROPOSED internal schemas below are reviewer-visible contract choices, not existing APIs or Brain approval of field spelling. Buffers are privately owned immutable snapshots by copy; no caller can mutate retained bytes. No raw bytes cross renderer IPC.
```ts
type RawRemoteRead = { attempt: number; bytes: Uint8Array; sha256: string;
  data: unknown; etag: string|null; generation: string|null; revision: number|null };
type ActualWritten = { bytes: Uint8Array; sha256: string; etag: string|null; generation: string|null };
type WriteAttempt = { attempt: number; attemptedSha256: string;
  rawRemote: RawRemoteRead|null; outcome: "success"|"conflict"|"failed"|"aborted" };
type ConditionalWriteOutcome =
  | { ok: true; actualWritten: ActualWritten; attempts: readonly WriteAttempt[] }
  | { ok: false; actualWritten: null; reason: "exhausted"|"aborted"|"write-error";
      attempts: readonly WriteAttempt[]; error: string|null };
type SyncFileOutcome = {
  observedRemote: { original: RawRemoteRead|null; retries: readonly RawRemoteRead[]; missing404: boolean };
  write: ConditionalWriteOutcome | { ok: null; actualWritten: null; reason: "not-needed" };
  localApply: { status: "not-attempted"|"applied"|"superseded"|"failed";
    basisContentGeneration: number; basisReplacementGeneration: number;
    appliedSha256: string|null; remoteDivergence: boolean; error: string|null };
  action: "unchanged"|"downloaded"|"uploaded"|"merged"|"failed"|"superseded";
};
```
Thrown storage failures are represented as truthful failed outcomes (or rethrown with the same retained attempt evidence), never converted to uploaded/merged success. generation/etag are distinct storage return fields; unavailable remains null, not guessed from one another. Raw revision absent remains null. Existing settings/history consumers can receive explicitly documented projections; library caller consumes full provenance. `localApply` is finalized by caller after syncFile's network result, not falsely filled by the network helper. Actual-write success does not force applied success.
Example initial-upload retry: original raw R0, initial local L0, initial hash H(L0), conflict; retry raw R1, production merge result W1 actually succeeds. Outcome retains original R0 + retry R1, actualWritten=W1/H(W1)/actualetag, never H(L0); caller revalidates current local L2 and applies production merge(L2,R1), reports applied hash H(A2) and remoteDivergence when A2 differs W1; later pending work remains. Existing conflict algorithm is unchanged; prior union W0 remains a merged input fact, never raw R1.
Example exhausted conflict: attempts all conflict, actualWritten=null, action failed, localApply not-attempted/failed as actual behavior, no success hash/status/ack; earlier successful settings write remains partial success. Download-only: raw original bytes retained, write not-needed, caller validates/apply independently; any ack needs per-operation representation proof below.


### 2. Captured batch and durable incarnation identity
Capture immutable batch BEFORE snapshots or relevant awaits, bound to queue init/path/device/account session. Assign operation incarnations stable within an initialized queue session, including loaded persisted entries; process-local sidecar identities may avoid persisted-format migration. Identity cannot be opKey/revision/timestamp: newer entries may match all three in the same millisecond. Acknowledge ONLY captured incarnations PROVEN represented by successful applicable outcomes. Session/init/account drift, failure, partial/superseded or missing proof retains work. Never drain by revision or infer ack from a revision bump.
Pin captured prefix identities while in flight; prohibit destructive compaction across captured prefix/later tail. Captured ADD + later DELETE must retain the DELETE, even if pure compactQueue would cancel an unrestricted combined array. Preserve pure compactQueue's existing rules WITHIN safe batches, reset precedence and current pending reset lookup in mergeLibrary329. A read snapshot is not an acknowledgment batch. Persist captured unacked operations durably throughout leases; crash/reinit cannot lose them. Release/abort ownership without deleting unacked work. Define exact internal capture/ack/release schema and identity lifecycle before admission; no persisted entry rewrite, session migration or queue reset by implication.
