## Hard boundaries
- A mode cannot import another mode's private runtime, hold its mutable refs, schedule its work, or mutate its persistence/visual state.
- Matching interfaces and mirrored implementations are required; a shared behavioral base class or a four-branch common hook does not satisfy separation.
- The router exports/imports value snapshots and switches the active owner. Late work from the prior owner is rejected.
- TTS is an infrastructure port consumed by Narrate, not an excuse to share Flow's runtime.
- Preserve each mode's current user behavior and known-defect evidence. Isolation is not a simultaneous feature rewrite or latency-tuning effort.
- Shared-core editing stays serialized until those shared owners are removed. Mode naming alone does not confer parallel safety.
- Future code consolidation requires a separate decision backed by independent contract/behavior evidence.

## Risks and responses
1. **Hidden lifecycle ownership causes regressions during extraction.** Capture the baseline and ownership map first, migrate one boundary at a time, and stop the affected wave on unrelated mode drift. Revert the scoped extraction if necessary; do not “fix” the other modes to accommodate it.
2. **Separation turns into a new shared abstraction.** Make sibling-import and cross-state-mutation guards part of acceptance. Temporary duplication is intentional.
3. **Old narration specs become misleading.** Keep them as dated reference, carry blocked scope stubs, and re-author against the isolated Narrate runtime. Preserve the 450 ms trusted-lag fact and qualified A5 result.
4. **Long unsized stage is mistaken for ready implementation.** Keep the head as Stub. Phase D must supply exact wave paths, tests/assertions, commands, failure ceilings, and rollback boundaries before certification.
